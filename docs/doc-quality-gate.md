# 文档质量门禁标准（doc-quality-gate）

> 来源：用户 2026-11-24 提供的门禁标准全文。用于对 overview-design.md、detailed-design.md、test-cases.md 做达标判定与自纠正。
> 判定：每项只能是 达标 / 部分达标 / 不达标 / 不适用。P0 任一不达标则门禁不通过；P0 全达标且 P1≥80% 建议通过；P0 全达标但 P1 70%~79% 有条件通过；其余不通过。

## 否决项 V-01~V-10

| 编号 | 否决项 |
|---|---|
| V-01 | 编造卖家精灵/1688/亚马逊官方 API、账号能力、合规结论或字段必然可得 |
| V-02 | 默认爬虫采集合法可用，未把平台条款、robots、反爬、验证码、账号风控、数据合规列为风险/待确认 |
| V-03 | 未体现“单品毛利润或月总销售额任一满足”，或未把筛选条件抽离为前端可配置 |
| V-04 | 未体现“商品池初次核验 → 候选池再次核验 → 内容生成 Agent”两阶段人工核验 |
| V-05 | 未体现“审核逻辑运营人员可编辑”，或未设计版本管理/回滚/审计 |
| V-06 | 后端未采用 MVC 分层，或 Controller 中承载核心业务逻辑 |
| V-07 | 详细设计缺少用例图、类图、关键时序图，或未给出 docs/attachments/ 本地路径与 Markdown 相对引用 |
| V-08 | 接口路径/方法/参数/响应/错误码前后矛盾，或数据库表无法支撑接口与业务逻辑 |
| V-09 | 测试用例不是业务逻辑导向，仅按接口字段堆 CRUD；或未覆盖业务规则/状态流转 |
| V-10 | 三份文档未列出“假设与待确认项”，或把待确认信息写成确定事实 |
